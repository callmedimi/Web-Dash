# راهنمای استفاده از پوشه plan (برای صاحب پروژه)

فایل‌های این پوشه به انگلیسی نوشته شده‌اند چون ایجنت پیاده‌ساز معمولاً با دستور انگلیسی دقیق‌تر عمل می‌کند. این فایل خلاصه فارسی است.

## ترتیب و محتوا
| فایل | محتوا |
|------|-------|
| 00_START_HERE | قوانین سخت برای ایجنت (هیچ‌وقت روی دستگاه واقعی تست نکن، بدون CDN، یک قدم در هر زمان) |
| 01_AUDIT_FINDINGS | همه باگ‌ها و ریسک‌های پیدا شده با شناسه F-xx |
| 02_TARGET_ARCHITECTURE | معماری نهایی، جدول‌های دیتابیس، قواعد API |
| 03 | فاز ۱: امنیت و پایدارسازی بدون تغییر قابلیت |
| 04 | فاز ۲: موتور Job پایدار (جایگزین ۵ سشن‌استور داخل حافظه) |
| 05 | فاز ۳: لایه SSH، پارسرها و تلمتری از Zabbix/Grafana (بدون SNMP مستقیم) |
| 06 | فاز ۴: چرخه امن تغییر (Plan → Approve → Apply → Verify → Rollback) |
| 07 | فاز ۵: فهرست قابلیت‌های اتوماسیون |
| 08 | فاز ۶: سیستم طراحی و پایه فرانت‌اند |
| 09 | فاز ۷: تک‌تک صفحات UI |
| 10 | فاز ۸: داکر، مانیتورینگ، بکاپ، CI |
| 11 | تست‌ها و چک‌لیست پذیرش نهایی |

## چطور به ایجنت بدهی
1. هر بار فقط `00_START_HERE.md` + فایل «فاز فعلی» را بده (نه همه فایل‌ها را با هم).
2. پرامپت پیشنهادی:
   > You are the implementer. Read plan/00_START_HERE.md fully, then execute plan/<فایل فاز> strictly step by step, starting at the first unfinished step. After each step run its Verify and reply in the report format from 00_START_HERE §5. Do not start the next step until Verify passes.
3. بعد از هر فاز، چک‌لیست «Smoke» در فایل 11 را اجرا کن و بعد برو فاز بعد.
4. اولین کار ایجنت Step 1.0 است: خواندن فایل‌هایی که من (معمار) نتوانستم ببینم و تکمیل 01_AUDIT_FINDINGS.

## چیزهایی که من ندیدم (صادقانه)
`templates/` و `static/` (گیت‌هاب دسترسی خودکار نداد)، پوشه `services/`، بخش پایانی `app.py` (بعد از حدود خط ۱۰۰۰)، و ماژول‌های reporting / vrf / ptp / arp / session_extractor / license_renewal. بنابراین نکات UI در فایل 01 فرض است و باید در Step 1.0 تأیید شود.

## ورودی‌هایی که فقط خودت می‌دانی
- نسخه Zabbix و Grafana و اینکه Grafana اجازه embed دارد یا نه.
- اسم/کلید آیتم‌های Zabbix برای CPU، حافظه، وضعیت اینترفیس (در `telemetry_map.yml`؛ ایجنت نباید حدس بزند).
- نمونه خروجی‌های واقعی دستورات VRP (بعد از پاک‌سازی IP و اسم) برای ساخت fixtureها.
- یک دستگاه lab برای تأیید دستورات rollback در VRP8.
